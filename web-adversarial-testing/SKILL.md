# Web 对抗性测试（探索性）

> 这是 `web-blackbox-testing` 的**可选补充**，不默认启用，不替代需求内标准用例。
> 输入是需求原文 + 已有八列用例表/运行包；输出是独立的 `risk-supplement.md`。

## 触发边界

适用：用户明确说「对抗性测试」「红队」「并发/幂等」「上线前风险」「状态迁移」，或要求检查标准用例之外的攻击面。

不适用：普通功能验收、回归、快速冒烟；这些走 `web-blackbox-testing`，不要自动扩大到本技能。

## 输出契约

1. 在 `<run-dir>/` 生成 `risk-supplement.md`，不修改标准用例的通过率。
2. 每条风险用 `AR-xx` 编号，包含：
   - 来源需求/用例编号
   - 风险假设（不是事实）
   - 攻击批次与最小操作
   - Oracle（UI/API/DB/下游，明确只读）
   - 结果、证据、置信度
   - 分类：`implementation_defect` / `requirement_risk` / `test_artifact`
3. 每条标准用例之外的检查都标注 **探索性**；**不计入需求覆盖**、不参与标准通过率。
4. 只有可复现、证据满足门槛的 `implementation_defect` 才能交 ONES；其余留在风险/决策台账。

## 执行流程

### 1. 建状态 × 操作 × 批量矩阵

先把需求中的对象、状态和操作列成矩阵；每格至少回答「允许/拦截/副作用/幂等」四项。

| 状态 \ 操作 | 新增 | 编辑 | 审核 | 取消/撤销 | 删除 | 批量 | 导入 | 导出 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 未审核 | | | | | | | | |
| 已审核 | | | | | | | | |
| 已关闭/失效 | | | | | | | | |

矩阵只作探索导航，不把未写进需求的单元格直接判成缺陷。

### 2. 定义不变量与 Oracle

至少写清：

- 唯一键、总量守恒、状态单调性、父子联动、权限边界、导出范围、日志完整性。
- Oracle 可为 UI、只读 API、只读 DB 或下游状态；不得用写库/改 DOM 代替业务操作。
- 需求没有定义的不变量标「待确认」，不要自行补规则。

### 3. 攻击批次

按风险从低到高、从可清理到不可逆排序；每批只改变一个变量：

- 重复提交：双击、回车+点击、刷新后重提、网络重试。
- 并发：两个会话同时编辑/审核/删除，检查最后写入、冲突提示与数据一致性。
- 导入：部分成功、重复键、空行、公式/HTML/超长文本、大小写/前后空格、超大文件。
- 状态迁移：已审核/已关闭/取消审核后的操作、父子状态错位、批量混合状态。
- 范围：跨地点/跨组织、全量视图、筛选后导出、分页边界、无权限对象。
- 数值：0、负数、上下限、超 1 单位、精度、科学计数法、空值。
- 幂等与恢复：超时/5xx 后重试、浏览器关闭再打开、检查点恢复。
- 可观测性：toast/内联错误/接口/数据四源是否一致，日志是否完整。

### 4. 最小化执行与留痕

- 使用独立测试数据和可回滚批次；禁止碰历史/生产数据，禁止猜测清理方式。
- 同一风险最多重试一次；基础能力错误快停并记录，不硬绕。
- 截图、接口响应、数据 diff 都存在 run 包 `evidence/`；截图只引用文件名，不写凭据。
- 不执行破坏性写入；DB 只读；需要写操作时走被测系统标准 UI/API。

### 5. 分类与收口

| 分类 | 进入哪里 | 说明 |
| --- | --- | --- |
| `implementation_defect` | 缺陷主账/ONES（满足门槛后） | 可复现实现问题 |
| `requirement_risk` | 产品决策/待确认 | 需求没定义或口径冲突 |
| `test_artifact` | 脚本/测试数据台账 | 测试自身或环境问题 |

输出末尾给：`已执行 AR-xx`、`确认缺陷`、`需求风险`、`测试伪影`、`未执行原因`。任何未完成项都要写明阻塞条件，不写“已验证”。

## 硬边界

- 只做标准用户操作；禁止 JS 注入改值、改 DOM/属性、对 disabled 强填。
- 只读 Oracle 不等于改库；不得为了“确认”写入生产/历史数据。
- 不泄露账号、密码、Token、Cookie、真实人名或客户路径。
- 不把探索性风险写成需求内缺陷；需求未定义时先记 `requirement_risk`。
