# 缺陷清单格式契约（web 产出 ↔ ones 解析）

> **单一来源**：`qa_skill_common/bug_report_schema.py`。生成侧（web）与解析侧（ones）都调它，
> 任一边改格式都会被下面这条自检拦住。
>
> 自检（往返契约测试）：`python scripts/qa_skill_common/bug_report_schema.py`

## 一、文件与标题格式

- 文件名：`YYYY-MM-DD_功能名_缺陷清单.md`，放在 `<产物根>/bug-reports/`（见 environment.md）。
- 文档头：

  ```markdown
  # 缺陷清单：<功能名>

  - 测试时间：YYYY-MM-DD
  - 环境：<环境地址>
  ```

- 每条缺陷标题（二选一，推荐第一种）：

  ```markdown
  ### BUG-01：<缺陷标题>
  ## BUG-01【一般】<缺陷标题>
  ```

  > 编号规则：`BUG-` + 字母数字/连字符。**标题不得自带前导冒号**（解析会自动去除）。

## 二、字段清单（每条缺陷下）

| 字段 | 必填 | 说明 | 示例 |
| --- | --- | --- | --- |
| `严重程度` | **是** | 一般 / 严重 / 致命 / 提示 / 建议 / 保留 | `一般` |
| `环境` | 否 | 缺省取文档头「环境」 | `http://t-xxx.ob.shuyilink.com` |
| `前置条件` | 否 | 复现所需数据/状态 | `存在剩余>0的计划` |
| `操作步骤` | 否 | 编号步骤 | `1.勾选 2.点生成` |
| `预期结果` | 否 | 应有行为 | `生成成功` |
| `实际结果` | 否 | 实测行为 | `无响应` |
| `复现率` | 否 | 如 `3/3` | `3/3` |
| `证据` | 否 | **纯文件名/通配符**，空格或顿号分隔 | `BUG-01.png export_*.xlsx` |
| `需求引用` | 否 | 需求点/PRD 条号 | `PRD-3.2` |
| `备注` | 否 | 补充说明 | `待产品确认` |

行格式统一为 `- 字段名：值`。

> **缺 `严重程度` 会被解析侧明确报 `[清单校验] ...缺必填字段 严重程度`**，不会静默丢字段。

## 三、证据规则

- 「证据」只写**纯文件名**（不带路径/分号/说明），多个用空格或顿号分隔，支持 `*`/`?` 通配符。
- 证据文件实际放在 `<产物根>/bug-reports/<功能名>/`；ones 解析时会自动把该目录的**一级子目录**纳入查找范围。
- 例：`- 证据：BUG-01_点击无响应.png export_*.xlsx`

| 侧 | 文件 | 调用 |
