# 导入 / 导出测试参考

## 导入功能测试流程

导入功能按以下固定步骤走，避免漏测（模板 / 页面提示 / 接口 / 结果核对都要覆盖）。
导入是否成功必须同时看页面导入窗口和 `simpleExcel/task/findOne` 接口，二者要一致：

1. 定位导入入口：可能在顶部按钮，也可能收在「更多」下拉里（点新增旁的 caret 展开）。
2. 打开导入界面，点「下载导入模板」保存模板文件。
3. 用 `bbt_helpers.parse_import_template(path)` 解析模板表头：`*` 前缀表示必填；
   把模板必填标记与需求文档逐字段核对（不一致即为缺陷线索）。
4. 按模板填测试数据，另存为新文件；至少覆盖：正常数据、缺必填、缺非必填、
   非法值 / 0 / 负数、重复数据。
5. 上传导入：Playwright 对 `input[type=file]`（常见 `el-upload__input`）
   直接 `set_input_files`，或点「新增导入」「覆盖导入」触发文件选择。
6. 观察页面导入窗口：上传后等待导入结果弹窗 / 区域出现。成功时窗口会明确显示
   「导入完成（成功 X 条，失败 Y 条）」等结果；失败时窗口会显示红色报错信息，
   并出现「下载失败文件」入口。
7. 同时核对接口与页面结果：失败必须截图保留红色报错与「下载失败文件」提示；必要时点击
   「下载失败文件」下载失败明细，归档为证据。接口只关注最新一次
   `linkim-pc/admin-console/simpleExcel/task/findOne` 的返回：
   `status / totalCount / successCount / failedCount / failedMessageList`
   才是最终成功数、失败数和失败原因；不要以 `import` 上传接口的返回作为最终依据。
   页面导入窗口与 `findOne` 接口结果不一致时，按缺陷记录。
8. 导入成功后刷新页面数据：当前导入多为异步导入，导入窗口显示成功不代表页面数据已刷新；
   重新刷新页面后，再核对列表 / 子表是否出现正确的新增 / 覆盖 / 去重 / 部分导入结果。
9. 清理本轮导入产生的测试数据。

导入类缺陷易漏点（按缺陷记录，不写成待确认）：

- 模板必填标记与需求不一致（需求必填、模板 / 后端非必填，或反之）。
- 缺必填字段仍返回成功且页面无报错提示，甚至静默不落库。
- 失败时页面没有红色报错信息，或没有提供「下载失败文件」入口。
- 导入成功但无任何页面提示（弹窗不关 / 不刷新 / 无 toast）。
- 导入窗口显示成功后刷新页面没有出现正确的新增 / 覆盖数据。
- 导入部分成功 / 部分失败时提示不明确，或重复导入产生脏数据。

## 缺陷易漏点补充

测试时要关注以下容易被误写成"待确认"的问题；除非需求明确允许页面与导出不一致，
否则按缺陷记录：

1. 导出内容必须和页面查询内容一致，包含字段值、数量、金额、单位、状态、日期/时间显示格式。
2. 页面显示日期为 `YYYY-MM-DD`，导出为 `YYYY-MM-DD 00:00:00` 或 `YYYY-MM-DD 23:59:59`，
   属于页面与导出格式不一致，按缺陷记录，不再默认写成待产品确认。
3. 页面字段为空但导出为 `null`、`undefined`、`0`、额外空格或默认值，按缺陷记录。
4. 页面金额/数量显示精度与导出精度不一致，且会影响核对、财务、库存或用户理解时，按缺陷记录。
