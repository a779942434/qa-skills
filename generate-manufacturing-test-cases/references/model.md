# 复杂链路的模型附录

标准/深度测试遇到跨对象流转时，在八列表之后补一个短附录，不重复抄用例正文。

## 1. 状态机

列出对象、合法状态和关键转移；至少覆盖：

- 允许的转移；
- 非法转移；
- 撤销/取消/回退；
- 重复操作是否幂等。

## 2. 数据流

```text
生产订单 → 分单 → 炉批次 → 炉次 → 配料单 → 订单计划 → 报工/看板
```

每个交接点写清楚：唯一 ID、数量、状态、时间字段和下游对象。

## 3. 不变量

按需求实际条款选择，不要脑补：

- 数量：子项合计 = 父项；已用 + 剩余 = 总量。
- 状态：只允许合法流转；已审核/已生产/已关闭对象不能非法回退。
- 身份：分单/批次/炉次/工序唯一维度不重复。
- 幂等：重复生成/审核/提交不产生重复对象。
- 时间：开始 ≤ 结束，同日/跨日/跨月/闰年边界明确。
- 派生：UI、API、SQL、下游使用同一公式和精度。
- 血缘：上下游保持同一 ID 和同一数量。
- 配置/权限：未配置、启用、停用、无权限时行为明确。

## 4. 结构化 sidecar

复杂链路同时产出 `coverage.json`，字段至少包含：

```json
{
  "cases": [{"id": "TC-01", "priority": "P0", "requirement_refs": ["R-01"], "invariant_ids": ["INV-01"]}],
  "invariants": [{"id": "INV-01", "name": "数量守恒", "case_ids": ["TC-01"]}],
  "exclusions": [{"requirement_ref": "R-02", "reason": "需求未定义"}]
}
```
