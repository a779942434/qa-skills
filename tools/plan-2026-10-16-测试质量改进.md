> 背景：本轮测试出现 **4 条误报**（#210564/#210565/#210566/#210445 被「拒绝后关闭」）+ 若干本地撤回项，
> 以及一批过程问题（污染共享环境、关闭他人标签页、绕过固化脚本等）。
> 本文用第一性原理定位根因，并给出**改什么 / 不改什么 / 怎么改**的计划。

## 一、第一性原理：测试判定的最小闭环

任何一条测试结论，等价于下面这条链：

```
采集证据  →  解释证据  →  比对基线  →  下结论
（四源）      （控件/语义）   （需求/口径）   （可复现）
```

四类失败都会产出**错误结论**，且都表现为"我报了、实际不是问题"：

| 环节 | 失败模式 | 本轮实例 |
|---|---|---|
| 采集证据 | 单次快照 / 单信号 / 未复测 | BUG-05「点击提交无任何请求」复测时未复现；组织切换「不刷新」；F15 只看未编辑态 |
| 解释证据 | 控件能力与语义误判 | #210565 把多选判成单选（只看了容器 class）；BUG-10 用 `fill`+ESC 判"不可改" |
| 比对基线 | 需求/口径基线过期或写反 | 污染源牌号"必填"已变更为非必填；TC-E04 预期写反；表头命名/文案类当缺陷 |
| 下结论 | 前提未就绪、环境受扰、无复现条件 | #210564 筛选需先「展开」；洗炉类在"规则未覆盖牌号"时下结论 |

## 二、更深的根因（一句话）

**我把"跑通脚本"当成了目标，把"最小证据链 + 复用固化实现"当成了成本。**

后果两条，且互相放大：
1. **成本**：几乎每步自己写一次性脚本 → 侦察/调试往返占掉绝大多数轮次
   （项目基线已量化：约 65% 轮次花在脚本往返、85% context 增长来自工具输出）
2. **质量**：自己写的判据弱于项目已有实现 → 误报 + 返工

## 三、技能项目现状：能力其实都有，但没被使用

| 项目已有能力 | 本应防住 | 我实际做法 |
|---|---|---|
| `judge_action`（四源判定，能识别 silent） | 单信号下结论 | 手工看 toast/截图 |
| `assert_control_type`（控件类型断言） | 把多选判成单选 | 只看 `.el-select` 容器 class |
| `select_multi_options`（多选专用） | 多选操作 | 自写 JS 点 `li` |
| `preflight.py`（页面/控件/主数据预检） | 前置未就绪就下结论 | 直接开测 |
| `field_contracts` / `page_registry` | 字段/页面反复试错、重复侦察 | 每轮重新探 |
| `qa_case.py`（批次闭环 + 检查点） | 脚本往返 | 每步内联脚本 |
| `data_factory` / `data_cleanup`（批次隔离、基线对比） | 污染共享环境 | 直接造数、不可逆 |
| `output.py emit`（判定字段不截断） | 截断导致误判 | 裸 dump + `tail`/`grep` |
| `references/element-plus-recipe.md`（SKILL 明示"做 UI 用例前先看"） | UI 控件误判 | **没看** |
| 红线 1「禁止 JS 注入改值」 | —— | 大量 `Object.getOwnPropertyDescriptor(...).set` 改 input |
| 红线 3「不得连现有标签页/共用 CDP」 | 干扰他人 | 连共享 9222 并 `close()` 他人 page |
| 红线 6「不碰历史数据」/ 造数留痕 | 污染环境 | 共享环境不可逆造数 |

**结论：不缺能力，缺"让能力成为默认路径"的机制。**

## 四、改什么 / 不改什么

### ✅ 不改（这些是对的，问题在我不在规范）
1. 红线条款本身（1/3/6/7/8）—— 我违反的，不是它们错了
2. 项目取向：技能瘦身 + 上下文预算闸门 + 文档红线条数门禁
3. `vendor-common.sh` / `sync-skills.sh` 的双层结构（源头唯一 + 各技能自带副本）
4. `qa_case.py` 批次闭环 + `output.py` 限长契约（方向正确）
5. 站点注册表/字段契约的两级可信度设计

### 🔧 要改（把"规范"变成"可执行 + 可自检"）

| # | 改进 | 落点 | 为什么能防住本轮错误 |
|---|---|---|---|
| I1 | **统一判定入口**：新增 `qa_action.py`（封装 `judge_action` + `assert_control_type` + `select_multi_options` + `emit`），规定「凡是要下结论的动作，必须经它执行」 | `qa_skill_common/` + SKILL 一处锚点 | 单信号判定、控件误判、截断误判三类一起收敛 |
